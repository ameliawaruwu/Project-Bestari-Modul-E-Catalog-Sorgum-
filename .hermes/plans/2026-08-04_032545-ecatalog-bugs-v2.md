## ISSUE ANALYSIS

### Bug 1: Tidak ada tombol kembali di halaman detail produk
**Root cause:** ProductDetailPage.tsx punya breadcrumb "Beranda > Produk > Nama" tapi tidak ada tombol kembali eksplisit. User yang masuk dari card produk butuh navigasi mundur.

**Fix:** Tambah tombol kembali (panah kiri + "Kembali") di atas breadcrumb yang panggil `setActiveTab('produk')`. Atau lebih baik: kembali ke halaman terakhir (produk/beranda). Simple approach: kembali ke `produk`.

### Bug 2: Discount display salah ("Diskon Promo (15000%)")
**Root cause:** CheckoutPage.tsx line 340:
```tsx
<span>Diskon Promo ({appliedDiscount}%)</span>
```
`appliedDiscount` nilainya NOMINAL RUPIAH (misal 15000), tapi display-nya pakai suffix `%`. Harusnya:
```tsx
<span>Diskon Promo</span> → - Rp 15.000
```
Atau `{t('Diskon Promo', 'Promo Discount')}` tanpa persen.

### Bug 3: Data user tidak sinkron DB→Admin→User
**Root cause:** Guest checkout membuat order tanpa user_id. Order #29 yang dibuat sebelumnya tidak terikat user. UsersTab BE endpoint `GET /api/admin/users` hanya return user dari tabel users — tapi guest checkout users tidak punya record di tabel users.

Review:
- BE: `POST /api/orders` tidak mewajibkan user_id (authOptional)
- BE: `GET /api/admin/users` hanya query tabel `users`
- Guest checkout users: data hanya tersimpan di kolom `shipping_address` JSON di orders, bukan di tabel users

**Fix:** Bukan bug DB — ini design SPA yang memang guest-friendly. Yang perlu diperbaiki: kalau user sudah login, pastikan user_id ke-save di orders. Verifikasi bahwa flow login→checkout sudah benar mengirim token.

### Bug 4: Voucher tidak mengurangi harga (discount calculation)
**Root cause:** CartPage.tsx line 52-53:
```ts
if (cleanCode === 'BESTARI10' || cleanCode === 'PROMO') {
  setAppliedDiscount(15000);
```
Hardcoded. CheckoutPage.tsx line 46:
```ts
const discount = appliedDiscount > 0 ? Math.min(appliedDiscount, subtotal) : 0;
```
Ini benar secara perhitungan. Tapi masalahnya: `appliedDiscount` disimpan di `AppContext` state. Saat navigasi Checkout → halaman lain → kembali ke Checkout, state `appliedDiscount` mungkin RESET ke 0 karena `useState(0)` di AppContext line 569.

Cek apakah ada flow yang menghapus appliedDiscount. Kalau iya, fix-nya: jangan reset appliedDiscount saat navigasi (hanya reset saat order complete).

### Feature 5: Kelola voucher di panel admin (BARU)
**Scope:**
- Tabel `vouchers` di MySQL: id, code, discount_amount, min_purchase, max_uses, used_count, is_active, expires_at, created_at
- BE: `GET/POST/PUT/DELETE /api/admin/vouchers` routes + service
- BE: `POST /api/vouchers/validate` untuk validasi kode voucher dari FE
- FE: CartPage ganti hardcode BESTARI10 → panggil `POST /api/vouchers/validate`
- FE: Admin panel — tab baru "Voucher" di sidebar + komponen VouchersTab

### Task 6: Buat BE voucher service & routes

**Objective:** CRUD voucher + validate endpoint.

**Files:**

**Step 1: Buat voucher_service.ts**

```ts
import { pool } from '../db';

export interface Voucher {
  id: number; code: string; discount_amount: number;
  min_purchase: number; max_uses: number | null;
  used_count: number; is_active: boolean;
  expires_at: string | null; created_at: string; updated_at: string;
}

export const voucherService = {
  async list() {
    const [rows] = await pool.query('SELECT * FROM vouchers ORDER BY created_at DESC');
    return rows as Voucher[];
  },
  async create(data: Partial<Voucher>) {
    const [res] = await pool.query(
      'INSERT INTO vouchers SET ?', data
    );
    return res;
  },
  async update(id: number, data: Partial<Voucher>) {
    await pool.query('UPDATE vouchers SET ? WHERE id=?', [data, id]);
  },
  async remove(id: number) {
    await pool.query('DELETE FROM vouchers WHERE id=?', [id]);
  },
  async validate(code: string, subtotal: number) {
    const [rows] = await pool.query(
      'SELECT * FROM vouchers WHERE code=? AND is_active=1 AND (expires_at IS NULL OR expires_at > NOW()) AND (max_uses IS NULL OR used_count < max_uses)',
      [code.toUpperCase()]
    );
    const v = (rows as Voucher[])[0];
    if (!v) return { valid: false, message: 'Kode voucher tidak valid atau sudah kadaluarsa.' };
    if (subtotal < v.min_purchase) return { valid: false, message: `Minimal belanja Rp ${v.min_purchase.toLocaleString('id-ID')} untuk menggunakan voucher ini.` };
    return { valid: true, discount: v.discount_amount, voucher: v };
  },
  async incrementUsage(id: number) {
    await pool.query('UPDATE vouchers SET used_count=used_count+1 WHERE id=?', [id]);
  }
};
```

**Step 2: Buat voucher_routes.ts**

```ts
import { Router } from 'express';
import { voucherService } from '../../services/voucher_service';
import { authenticate } from '../../middleware/auth';

const router = Router();

router.get('/', authenticate, async (req, res) => {
  const vouchers = await voucherService.list();
  res.json({ data: vouchers });
});
router.post('/', authenticate, async (req, res) => {
  await voucherService.create(req.body);
  res.json({ message: 'Voucher created' });
});
router.put('/:id', authenticate, async (req, res) => {
  await voucherService.update(Number(req.params.id), req.body);
  res.json({ message: 'Voucher updated' });
});
router.delete('/:id', authenticate, async (req, res) => {
  await voucherService.remove(Number(req.params.id));
  res.json({ message: 'Voucher deleted' });
});

export default router;
```

## Risks & Tradeoffs

- **Voucher validation race condition:** `used_count < max_uses` check dan increment tidak atomic. Untuk traffic rendah acceptabel; nanti bisa upgrade pakai `SELECT ... FOR UPDATE` atau Redis lock.
- **Guest checkout user:** Tidak ada fix — by design. Guest tidak perlu register. User yang mau history lengkap harus login dulu.
- **Migration rollback:** 005_vouchers.sql tidak ada down script — tabel bisa di-DROP manual.
